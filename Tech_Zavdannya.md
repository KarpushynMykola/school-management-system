# Технічне завдання

**Тема продукту:** Система обліку учнів та навчальних класів школи.

## 1. Мета і завдання продукту

**Мета:**
Розробка веб-орієнтованої інформаційної системи для автоматизації процесів обліку учнів, управління навчальними класами та забезпечення зручної взаємодії між учасниками навчального процесу (вчителями та учнями).

**Завдання:**

- Створення єдиної електронної бази даних учнів школи.
- Цифровізація процесів формування класів, призначення класних керівників та переведення учнів.
- Забезпечення швидкого доступу до інформації за допомогою інструментів пошуку та фільтрації.
- Реалізація рольової моделі з розмежуванням прав доступу для забезпечення конфіденційності та безпеки даних.

---

## 2. Загальні функціональні та нефункціональні вимоги

### Функціональні вимоги:

1. **Управління обліковими записами:** Система повинна дозволяти авторизацію за ролями («Вчитель» / «Учень») із відповідним обмеженням прав доступу.
2. **Облік учнів:** Можливість створювати нові записи учнів, редагувати їхні дані та змінювати статус («Навчається», «Вибув», «Зарахований»).
3. **Управління класами:** Можливість створювати класи (наприклад, 10-А), призначати класних керівників та розподіляти класи за паралелями і літерами.
4. **Розподіл та переведення:** Можливість призначати учнів до класів та виконувати масове або поодиноке переведення між класами.
5. **Пошук та фільтрація:** Функціонал пошуку учнів за прізвищем, класом або поточним статусом.

### Нефункціональні вимоги:

1. **Продуктивність:** Час відгуку системи на запити пошуку або фільтрації не повинен перевищувати 2 секунд при обсязі до 5000 записів.
2. **Безпека даних:** Хешування паролів у базі даних (MongoDB) через алгоритм bcrypt.
3. **Контроль доступу:** Аутентифікація користувачів через JWT (JSON Web Token) для захисту API-маршрутів Node.js/Express.
4. **Зручність використання:** Інтерфейс React має бути мінімалістичним та забезпечувати інтуїтивну навігацію з доступом до основних функцій не більше ніж за 3 кліки від головного екрана.
5. **Масштабованість:** Архітектура сервера має бути спроектована таким чином, щоб витримувати щонайменше 200 одночасних користувачів без втрати продуктивності.

---

## 3. Обмеження

- **Технологічний стек:** Продукт має бути розроблений виключно з використанням затвердженого стеку технологій:
  - Backend: Node.js / Express
  - Frontend: React
  - Database: MongoDB
- **Обсяг даних:** Система оптимізується та тестується на базі, що містить до 5000 записів.
- **Рольова модель:** На даному етапі розробки передбачено лише дві ролі («Вчитель» та «Учень»), без створення окремих панелей для адміністраторів вищого рівня (наприклад, директора) чи батьків.
- **Навантаження:** Гарантована стабільна робота обмежується 200 одночасними активними сесіями.

---

## 4. Очікувані результати

- Готовий до впровадження програмний продукт (веб-додаток), що відповідає всім зазначеним функціональним та нефункціональним вимогам.
- Створена та налаштована база даних MongoDB для безпечного зберігання інформації про учнів та класи.
- Зручний та швидкий React-інтерфейс, який дозволить персоналу школи виконувати рутинні завдання з обліку в межах 3 кліків.
- Надійний та захищений (через JWT та bcrypt) Backend на Node.js/Express, здатний ефективно обробляти запити користувачів.
- Мінімізація паперової роботи та суттєве скорочення часу на пошук інформації про учнів, формування звітів щодо наповненості класів та процеси переведення учнів.
